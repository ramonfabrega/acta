# v0 — the contract

What the first working acta is, precisely enough that three people (or three
agents) can build its parts in parallel and have them meet. Read CLAUDE.md
first; this file does not repeat the thesis, only the shapes. Facts marked
*(spike)* were measured live on 2026-10-23; see `docs/SPIKE.md`.

## Scope

In: `acta new`, a room page behind a capability link, Scribe with the agent
socket, utterances, the paragraph rule, the book, the brain's events socket,
per-track recording, the R2 copy, `acta tail|book put|export|sync|doctor`,
and `acta test` with synthetic speakers. Out: comments/edits on the book,
Access enforcement beyond JWT verification when configured, any metered
model, lore's adapter.

## Layout

```
src/worker.ts            Hono app: routes below, auth, mints tokens, talks to Scribe
src/scribe.ts            Durable Object `Scribe`, one per meeting (SQLite)
src/rtk.ts               RealtimeKit REST client, zod on every response
src/room.ts              the room page as a template string (no bundler)
src/core/schemas.ts      zod: Env, agent events, webhooks, Utterance, Paragraph, Book, events frames
src/core/paragraphs.ts   pure paragraph state machine
src/core/book.ts         book sections <-> Markdown, transcript rendering
src/core/webhook.ts      rtk-signature verification (WebCrypto RSA-SHA256)
src/core/ids.ts          slugs, random tokens
cli/acta.ts              Bun CLI (`bun cli/acta.ts …`; `bun link` gives `acta`)
cli/commands/*.ts        one file per command, each exports {name, summary, args, run}
cli/llms.ts              `acta --llms`: generated from the command table
test/core/*.test.ts      bun tests for src/core
test/synth/bot.html      the synthetic participant page (Core SDK only)
test/synth/speaker.ts    launches headless Chromium with a WAV as microphone
test/synth/fixtures/*.json  scripted dialogues
scripts/setup.ts         idempotent: presets, webhook registration, secrets check
```

`web/` stays empty in v0; no `assets` binding. The room page is served by
the Worker from `src/room.ts`. The only front-end dependencies are the two
RealtimeKit CDN bundles and `marked` for the book pane, all version-pinned.

## Environment

`wrangler.jsonc` vars (non-secret): `RTK_APP_ID`, `CF_ACCOUNT_ID`,
`PUBLIC_HOST` (`acta.ramonfabrega.com`), `CF_ACCESS_TEAM_DOMAIN`,
`CF_ACCESS_AUD` (both may be empty: Access verification is off until set).

Secrets (`wrangler secret put`): `RTK_API_TOKEN` (Cloudflare token, Realtime
Admin), `ACTA_TOKEN` (one operator bearer: CLI, brain, events socket).
There is no webhook secret: RealtimeKit signs with RSA-SHA256 and publishes
the public key at `https://api.realtime.cloudflare.com/.well-known/webhooks.json`
(`{success, data: {publicKey: "-----BEGIN PUBLIC KEY-----…"}}`). Fetch it
lazily, cache in module scope, re-fetch once on a verification failure.

`Env` is parsed with zod at the top of `fetch` (`EnvSchema.parse(env)`),
bindings included (`SCRIBE: DurableObjectNamespace`, `MEETINGS: R2Bucket`,
`AI: Ai`).

Local CLI config: `ACTA_URL` (default `https://acta.ramonfabrega.com`) and
`ACTA_TOKEN` from the environment, else `passage show tokens/cloudflare/personal/acta/acta-token`.

## RealtimeKit facts the code relies on

- REST base `https://api.cloudflare.com/client/v4/accounts/{CF_ACCOUNT_ID}/realtime/kit/{RTK_APP_ID}`,
  `Authorization: Bearer RTK_API_TOKEN`. Success bodies are `{success: true, data: …}`;
  lists are `{success, data: [...], paging}`; errors `{success: false, error: {code, message, details}}`.
- Create meeting: `POST /meetings` with
  `{title, transcribe_on_end: false, summarize_on_end: false, session_keep_alive_time_in_secs: 60, ai_config: {transcription: {language: "multi", keywords}}}`.
  **Never** `record_on_start` (it records the agent alone *(spike)*) and never
  `transcribe_on_end: true` with `multi` (400 *(spike)*). Response `data.id`.
- Add participant: `POST /meetings/{id}/participants`
  `{name, preset_name: "human" | "agent", custom_participant_id}` → `data.{id, token}`.
  Tokens are JWTs valid 100 days. Presets `human` (`transcription_enabled`,
  `can_edit_display_name`) and `agent` (`hidden_participant`, no media) exist
  on the app; `scripts/setup.ts` asserts them.
- Agent socket: `GET https://api.realtime.cloudflare.com/agent-ws/v1?subscriptions=transcript,participant[&connection_id=…]`
  opened from the DO with `fetch(url, {headers: {Upgrade: "websocket", Authorization: "Bearer <agent token>", "Sec-WebSocket-Protocol": "realtimekit.v1"}})`
  and `res.webSocket.accept()`. Frames are `{category, name, data}`; requests are
  `{category: "request", request_id, name, data: {}}` answered by
  `{category: "result", request_id, data | error}`. Send `connection.get`
  once after open and store `data.connection.id`; send `connection.ping`
  every 20 s and reconnect if no result within 10 s. Close codes: 1000
  `session_ended` (do not reconnect; a new session needs a new connection),
  1013 `queue_overflow` (reconnect without `connection_id`), 1013
  `upstream_lost` / `upstream_unavailable` (resume with `connection_id`,
  backoff), 4403 (bad token), 4409 `replaced` (stop). Closing with 1000 makes
  the agent leave at once; anything else leaves a 5 s grace.
- Agent events *(spike)*: `session.started {session: {id, meeting_id, started_at}}`,
  `session.ended {session, reason}`, `participant.join|leave {participant: {peer_id, participant_id, custom_participant_id, display_name, preset_name?, …}}`,
  `transcript.received {text, is_final, started_at, ended_at, confidence, speaker: {peer_id, participant_id, custom_participant_id, display_name}}`.
  `started_at`/`ended_at` are ISO strings to the second; `started_at` is
  server receipt and `ended_at` is unreliable. There is no segment id.
  Partials arrive 2–4 per second per speaker. A `participant.join` for a
  `peer_id` can repeat (Firefox fails media and retries with the same peer)
  and a join is not proof of media.
- Track recording: `POST /recordings/track {meeting_id}` (omit `user_ids`:
  every current and future participant, audio-only WebM per participant,
  up to 100). Requires a live session. Stop with
  `PUT /recordings/{id} {action: "stop"}`; it also stops when the session ends.
  *(live 2026-10-23)* the start answer is a 200 **without** a top-level `id`;
  the id arrives with the first `recording.statusUpdate` (`RECORDING`, ~3 s
  later), and a second start answers 409 "already exists". `GET /recordings/{id}`
  has the files: `download_url: {links: [{layer_name, download_urls: {<file>: {download_url, peer_id, custom_participant_id}}}]}`,
  `download_url_expiry` seven days out, one file per participant **including
  the agent's silent track** (skip `custom_participant_id: "acta-agent"`).
  File names are `{prefix}_{user}_{peer}_peer_audio_{ms}.webm`; we store them
  as `recordings/<speaker>-<peer8>.webm`.
- Webhooks list: `GET /webhooks` answers **404 "Webhook not found"** when the
  app has none (treat as empty); `GET /webhooks/all` lists event *names*.
- Webhooks: `POST /webhooks {name, url, events, enabled}`; events used:
  `meeting.started`, `meeting.ended`, `meeting.participantJoined`,
  `meeting.participantLeft`, `recording.statusUpdate`. Headers
  `rtk-signature` (base64 RSA-SHA256 over the raw body), `rtk-uuid`
  (dedupe), `rtk-webhook-id`. Payloads carry `event` and a `meeting.id`;
  `recording.statusUpdate` carries `recording.{id, status, downloadUrl?, audioDownloadUrl?, downloadUrlExpiry?, outputFileName?, …}`
  and, for track recordings, URLs grouped by layer (`download_url[].{layer_name, download_urls: {<file>: {download_url}}}`);
  statuses `RECORDING | UPLOADING | UPLOADED | ERRORED`. Answer 2xx fast;
  do the copy in `waitUntil`. Unknown shapes must not throw: validate with
  `.passthrough()` and log what did not parse.
- Sessions: `GET /meetings/{id}/active-session` → `data.{id, status, live_participants, recording_status, …}`.

## Data shapes (`src/core/schemas.ts`)

```ts
Utterance = { t0: number, t1: number, speaker: string, userId: string, peerId: string,
              text: string, lang: string | null, final: true, engine: "nova-3", conf: number | null }
```
`t0`/`t1` are **epoch ms from Scribe's own clock**: `t1` = receipt of the
final; `t0` = receipt of the first partial from that `peerId` since its last
final, else `t1 - max(800, 60 * words)` ms. `speaker` is the display name
slug at join time; `userId` is `custom_participant_id`. `lang` is `null` in
v0 (nova-3 `multi` does not report it). One JSON object per line, in `t1`
order; this file is `meetings/<id>/utterances.jsonl` in R2 and the contract
with lore and the batch passes.

```ts
Paragraph = { id: string, t0: number, t1: number, speaker: string, userId: string,
              text: string, utterances: number[] /* seq */, asides: Aside[] }
Aside = { speaker: string, text: string, t0: number }   // inline as "[ana: mhm]"
```

Book: ordered sections `summary`, `decisions`, `actions`, `notes`,
`transcript`. Each is Markdown without its own H2. `transcript` is
generated from paragraphs (`**speaker** · hh:mm:ss` line then the text,
asides inline in brackets); the others are written by the brain. Rendered
file: `# <title>` + `## Summary` … in that order, empty sections omitted
except `transcript`.

Events frames on `/m/<id>/events` (one JSON object per text frame):
```
{type:"hello", meetingId, title, since, state, digest}   on connect (once); digest = 60000 ms, or null with ?each=1
{type:"started", sessionId, at}
{type:"participant", event:"join"|"leave", speaker, userId, at}
{type:"paragraphs", paragraphs: Paragraph[], at}         the main one: everything closed since the last digest, ≤ 1/minute
{type:"paragraph", paragraph: Paragraph}                  only on a socket opened with ?each=1 (acta tail --each)
{type:"agent", event:"lost"|"connected"|"gap", at, detail}   the agent socket to RealtimeKit dropped, came back, lost events
{type:"book", section, updatedAt}                         when the brain writes
{type:"ended", at, reason, utterances, paragraphs}
```
Never partials, never per-utterance frames. The digest is the brain's
cadence: three people make a few hundred paragraphs an hour (measured
2026-10-23, `docs/MEETING1.md`), and every frame is a notification, so
paragraphs are batched per minute and flushed before `ended`. The room
page's socket (`/m/<id>/ws`) receives `{type:"book", sections:
Record<section, markdown>}` on every book change and `{type:"paragraph", …}`
per paragraph for the live transcript pane.

## The paragraph rule (`src/core/paragraphs.ts`)

Pure, deterministic, testable without a DO:

```ts
createParagraphs(opts?: {gapMs?: 4000, capMs?: 120000, backchannelMaxWords?: 5,
                         backchannelMaxMs?: 3000, continueWithinMs?: 4000})
  .push(u: Utterance & {seq: number}): Paragraph[]   // paragraphs closed by this utterance
  .flush(nowMs: number): Paragraph[]                 // close on gap/cap; call from an alarm
  .nextDeadline(): number | null                     // when flush would close something
  .state(): JSON-serialisable; restore(state)       // Scribe persists it between wakeups
```
Rules: a new paragraph opens on the first utterance. Same speaker within
`gapMs` of the previous `t1` extends it; past `gapMs` or past `capMs` from
`t0` it closes and a new one opens. Another speaker's final of
≤ `backchannelMaxWords` words and `< backchannelMaxMs` duration is a
*candidate* aside: it is held; if the floor-holder speaks again (a partial
or a final) within `continueWithinMs` of the candidate's `t1`, the
candidate becomes an aside and the paragraph continues; otherwise it closes
the paragraph and opens a new one for that speaker. `continueWithinMs`
equals `gapMs`: the decision is deferred to what follows, because finals
arrive a second or two after speech and a shorter bound was never met live
(34 sandwiched interjections became paragraphs in meeting 1). A rejected
candidate replays as speech, so it and the paragraph it interrupted can
close at the same instant. Any longer utterance from another speaker closes
the paragraph. The aside stays in the JSONL as its own utterance.

Two refinements the live runs forced: `partial(userId, atMs)` is called on
every non-final frame so the machine knows the floor-holder is still
talking (no gap-close mid-monologue, and a speaker with live partials holds
a *provisional* floor before their first final, so an "mhm" during the
opening sentence is a candidate, not a paragraph); and a candidate leaves
the list the moment it is inlined, placed before the utterance it fell in a
pause of or after the one it overlapped, never twice.

## HTTP API (`src/worker.ts`)

Auth: `bearer` = `Authorization: Bearer ACTA_TOKEN` (constant-time compare);
`cap` = `?k=<invite>` or `X-Acta-Key`, the per-meeting capability minted by
`acta new`. If `CF_ACCESS_*` are set, routes marked `cap` additionally
require a valid `Cf-Access-Jwt-Assertion` (RS256 against
`https://<team>/cdn-cgi/access/certs`, `aud` = `CF_ACCESS_AUD`) and the
JWT's `email` becomes the participant identity.

```
GET  /healthz                              → {ok, version}
POST /api/meetings            bearer       {title, keywords?: string[]}
                                           → {id, title, url, createdAt}   url = https://PUBLIC_HOST/m/<id>?k=<invite>
GET  /api/meetings            bearer       → [{id, title, createdAt, state}]   (RTK list + Scribe state when known)
GET  /api/meetings/:id        bearer       → Scribe status: {state, title, session, participants[], counts, recording, copies[]}
GET  /api/meetings/:id/utterances  bearer  → application/x-ndjson
GET  /api/meetings/:id/paragraphs  bearer  → Paragraph[]
GET  /api/meetings/:id/export      bearer  → text/markdown (book + transcript)
GET  /api/meetings/:id/files       bearer  → [{key, size, uploaded}] under meetings/<id>/ in R2
GET  /api/meetings/:id/files/*     bearer  → the object (streams)
POST /api/meetings/:id/copy  bearer       → {recording:{id,status}, files, copies[]}  Scribe re-reads the
                                           recording record and copies what is missing, now (409 without a recording)
POST /api/meetings/:id/end         bearer  → forces the end-of-meeting sequence (for tests)
GET  /m/:id                   cap          → room page (HTML)
POST /m/:id/join              cap          {name} → {token, userId, speaker}   mints a `human` participant
POST /m/:id/joined            cap          {peerId} → 204   the page's roomJoined = media confirmed
GET  /m/:id/book              cap|bearer   → {title, sections}
PUT  /m/:id/book/:section     bearer       text/markdown body → {updatedAt}; section ∉ {transcript}
GET  /m/:id/ws                cap          WebSocket for the page
GET  /m/:id/events            bearer       WebSocket for the brain (token also accepted as ?token= or
                                           as the second entry of Sec-WebSocket-Protocol: `acta.v1, <token>`,
                                           because the harness Monitor cannot set headers)
POST /hooks/rtk               signature    RealtimeKit webhooks; 200 fast, work in waitUntil
GET  /synth/bot                            test/synth/bot.html (token in the URL fragment; no auth: the token is the auth)
```

Every route that touches a meeting forwards to `env.SCRIBE.getByName(id)`
via RPC methods on the DO class (not internal fetch): `init`, `status`,
`join`, `mediaConfirmed`, `book`, `putBook`, `utterances`, `paragraphs`,
`hook`, `end`, and `fetch` only for the two WebSocket upgrades.

## Scribe (`src/scribe.ts`)

One instance per meeting, named by the RealtimeKit meeting id. SQLite via
`ctx.storage.sql`; tables `meta`, `participants`, `utterances`,
`paragraphs`, `book`, `events` (webhook dedupe), `copies`, `log` (every
`log()` line; `log.jsonl` in R2 at the end and again after the copies).
Migrations run in the constructor with `blockConcurrencyWhile`.

Lifecycle: `init({meetingId, title, invite, agentToken, keywords})` → state
`idle`, opens the agent socket at once. `session.started` → `live`, frame
`started`. `participant.join` of a non-agent → upsert by `peer_id`
(idempotent), frame `participant join` when the peer is new or returns
after a real leave (`left_at` set); a second join of a peer still in the
room (the failed-first-attempt case) is silent. A transcript from a peer
before its join registers it and emits the same frame. `mediaConfirmed(peerId)`
(from the page) or the first transcript from that peer marks the participant
present; the **first** present human starts track recording (once per
session; store the recording id). `transcript.received` with `is_final: false`
→ stamp the peer's first and latest partial (`src/core/timing.ts`: a 3 s
silence between partials starts a new stamp; the map is cleared when the
agent socket closes). `is_final: true` → `t0` from the stamp when it is
plausible for the word count, else an estimate, never `t1`; append
utterance, push through the paragraph machine, persist machine state,
store closed paragraphs, append to the transcript section, send `paragraph`
to `each` sockets and the room (tag `room`), and arm the digest (one
`paragraphs` frame to `digest` sockets at most every `DIGEST_MS` = 60 s).
`agent` frames go out when the agent socket closes unexpectedly, comes
back, or replays `session.started` on resume (a gap). Set the DO alarm to
`min(pingDue, paragraphs.nextDeadline(), digestDue, leaveGrace)`.
`participant.leave` → mark left; when no human is present schedule
end-of-meeting in 20 s (a reload must not end the meeting); a join cancels
it. End-of-meeting: close the agent socket with 1000, `flush`, the last
digest, write `meetings/<id>/utterances.jsonl`, `paragraphs.json`,
`book.md`, `meta.json`, `log.jsonl` to R2, frame `ended`, state `ended`.
Webhooks: `recording.statusUpdate`
`UPLOADED` → for every download URL, stream to `meetings/<id>/recordings/<file>`
(`fetch` → `MEETINGS.put` with the body stream), record in `copies`;
`ERRORED` → record. `meeting.ended` → if still live, run end-of-meeting.
The agent socket is outbound and does not hibernate the DO: the 20 s ping
alarm keeps the object alive for the meeting's duration, which is the
intended cost.

Inbound WebSockets use the hibernation API (`ctx.acceptWebSocket(ws, [tag])`,
`webSocketMessage/Close`); on `hello`, the events socket also receives the
`ended` frame if the meeting already ended, so a late brain is not left hanging.

## Room page (`src/room.ts`)

Plain HTML string with placeholders. Flow: page loads with `k` in the query
→ shows name (prefilled from Access email when present, else last name from
`localStorage`) and a "Join" button → on click, `getUserMedia({audio: true})`
first *(spike: the kit races the permission prompt)*, then
`POST /m/:id/join` → `RealtimeKitClient.init({authToken, defaults: {audio: true, video: false}})`
→ `<rtk-meeting>` gets the meeting object (host style untouched; size with
`height` only). `roomJoined` → `POST /m/:id/joined {peerId}`. Layout:
meeting left, book pane right (collapsible, ~380px), rendered with `marked`,
updated over `/m/:id/ws`; a small live-transcript strip under the book.
Pinned CDN: `@cloudflare/realtimekit@2.0.4`, `@cloudflare/realtimekit-ui@2.0.3`,
`marked@15` from cdnjs or jsdelivr.

## CLI (`cli/`)

Built on incur (ported 2026-10-23; v0 shipped a hand-rolled parser).
`acta new <title> [--keywords a,b]` answers `{id, url, title, createdAt,
events}`; `acta meetings` answers `{count, live, meetings[]}`; `acta tail
<id> [--frames]` streams `/events` one line (or, with `--frames`, one
frame object) per frame and exits 0 on `ended` (also the manual fallback
for the brain); `acta book put <id> <section> [file|-]`; `acta book show
<id> [--section s]`; `acta export <id> [--out file]`; `acta copy <id>` (vendor → R2 now: the
recovery for a recording doctor lists; exit 1 when nothing was listed or a
track failed); `acta sync [<id>]` →
`~/.acta/meetings/<id>/` (skips files already present with the same size,
one row per meeting as it lands); `acta doctor` lists meetings whose state
is `ended` with recordings not yet copied, or `live` for more than 3 h;
`acta test` (below). The command table is `cli/cli.ts`: zod schemas for
args and options, bodies in `cli/commands/`, so `--help`, `--llms` (index),
`--llms-full` (manifest), `--schema`, `--mcp` and `acta skills add` are
generated. Output is TOON on a pipe, `--json` or `--format yaml|md|jsonl`
on request; `doctor`, `sync` and `test` stream their report, then end with
incur's error envelope (exit 1) when something needs a human. Exit 1 on
any API error with the server's message and on bad arguments (incur's
validation; the old exit 2 is gone).

## Synthetic speakers (`test/synth/`, `acta test`)

`speaker.ts`: `launchSpeaker({url, wav, tag})` runs
`~/Library/Caches/ms-playwright/chromium-*/…/Google Chrome for Testing`
(or `ACTA_CHROME`) with
`--headless=new --no-sandbox --disable-features=AudioServiceSandbox,AudioServiceOutOfProcess --use-fake-device-for-media-stream --use-fake-ui-for-media-stream --use-file-for-fake-audio-capture=<wav> --autoplay-policy=no-user-gesture-required`
loading `/synth/bot#authToken=…&tag=…&relay=<url>`; returns `{pid, stop()}`.
`bot.html` *(spike, works)*: Core SDK, canvas waveform as camera, auto-join,
relays `roomJoined`/finals/errors to `relay` via POST. Voices: macOS `say`
(`Eddy (Spanish (Mexico))`, `Samantha`, …) → `ffmpeg` → 48 kHz mono
`pcm_s16le` WAV; the fixture's `startAt` offsets become leading silence so
two speakers overlap exactly as scripted. Fixture:

```json
{ "title": "two speakers", "speakers": [{"tag": "ana", "voice": "Eddy (Spanish (Mexico))"}, {"tag": "ben", "voice": "Samantha"}],
  "lines": [{"at": 0, "who": "ana", "text": "…"}, {"at": 6.5, "who": "ben", "text": "mhm"}, …] }
```

`acta test [--fixture f.json] [--keep]`: `POST /api/meetings` → for each
speaker `POST /m/:id/join` → build WAVs → launch speakers → read `/events`
until `ended` (or 3 min) → fetch utterances + paragraphs → assert: every
speaker produced ≥ 1 final; speakers attributed correctly (text ↔ tag);
the `mhm` line is an aside, not a paragraph; utterances are `t1`-ordered;
R2 has `utterances.jsonl`; print a table and exit non-zero on failure.
`--keep` leaves the meeting live for a human to join.

## Conventions that bite

- `TZ=UTC bun test`; no `as X` on I/O; zod `.parse` at every boundary and
  `.passthrough()` on vendor payloads.
- Log lines are one JSON object: `{at, meeting, ev, …}`, on the console
  and in Scribe's `log` table; the meeting's `log.jsonl` in R2 is the
  record (Workers Logs keeps a few days).
- Nothing from a meeting is ever written under the repo.
- Deploy only between meetings (`acta meetings` shows nothing `live`).
